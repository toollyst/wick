# The workspace's unit tests that do not pass on macOS CI's runners, each with
# the reason. tools/macos/check-unit-tests.py runs every test of every crate
# it names (the jailer's run as root in their own step) and fails on:
#   - a failure not listed here;
#   - an entry whose test passes, is ignored or does not run;
#   - an entry naming a test that does not exist.
# So nothing goes unrun silently, and the list cannot rot.
#
# Root only, among the jailer's tests: test_pid_suspend_binding and
# test_self_check_under_load (platform::macos::freezer) call pid_suspend.
# Run by a plain user they print "NOT RUN: pid_suspend needs root" and pass
# without having run: as a user the call waits on taskgated, which can put
# up a password dialog and block every task-port request of the host (the
# comment at test_pid_suspend_binding). CI's "Jailer unit tests" step runs
# both as root, as does `sudo env RUST_TEST_THREADS=1 <jailer test binary>`.
#
# One thread, always: upstream runs its unit tests with RUST_TEST_THREADS=1
# (tests/host_tools/cargo_build.py cargo_test), and the jailer's need it.
# Its own tests::test_sanitize_process and tests::test_fds_close_range close
# every descriptor of the process from 3 up, and the freezer's tests fork: in
# a threaded run (a plain `cargo test -p jailer`) a test loses its
# descriptors to the first two, and a fork made by another test's thread
# keeps a file lock a test has just dropped. Measured on macOS 27.2, without
# root: threaded, one run stayed at 0% CPU until it was killed and one
# aborted ("IO Safety violation: owned file descriptor already closed");
# threaded without those two tests, test_a_write_after_the_read_is_applied
# found the lock still held ("Busy"); with one thread, 47 of 48 pass in 84 s
# and the 48th, upstream's resource_limits::tests::test_set_resource_limits,
# fails at raising the descriptor limit, which takes root. The product makes
# its forks from one thread (the jailer has no other).
#
# Root only, among vmm's tests: two cases of
# ext::sandbox::macos::tests::test_unfiltered_syscalls_are_limited_by_their_rule,
# pid_suspend and pid_resume with their rule lifted (the cases that show the
# rule is what refuses them). Run by a plain user each prints
# "<call> lifted: NOT RUN: as a plain user it waits on taskgated, ..." to
# standard error and the test passes without them, for the reason above (the
# comment at the test). The same two calls with the rule in place run for
# every user: the sandbox refuses them before taskgated is asked. No CI step
# runs vmm's tests as root (check-unit-tests.py and the macos-seatbelt job
# run them as the runner's user), so CI does not run the two lifted cases;
# as root, with no NOT RUN line:
# `sudo <vmm test binary> --exact
# ext::sandbox::macos::tests::test_unfiltered_syscalls_are_limited_by_their_rule
# --nocapture`.
#
# Format: <kind> <crate> <test path>, below a comment that gives the reason.
# <crate> is a name of check-unit-tests.py's: the package, or compat-<name> for
# crates/compat/<name>. kind:
#   no-hvf      creates a VM: hv_vm_create fails where Hypervisor.framework
#               is missing, as on GitHub's macOS runners (virtual machines):
#               HV_UNSUPPORTED, CreateVm(Error(45)) or Error(45) (ENOTSUP);
#               and without the hypervisor entitlement: HV_DENIED,
#               CreateVm(Error(1)) or Error(1) (EPERM). Each passes on an
#               M1 Pro (macOS 27.2) signed with it, alone in its process
#               (tools/macos/test.sh, one VM per process); that run is where
#               these are tested.
#   linux-path  the test reads a Linux path itself
#   error-text  the test builds Linux's error text from a Linux errno number
#   bug         a wick bug or difference to fix (root cause first)
#
# Measured on an M1 Pro, macOS 27.2, 2026-11-13, unsigned (as CI), one test
# thread, then each failure alone unsigned and signed:
#   vmm --lib: 1038 tests; 850 pass, 138 fail, 50 ignored (the ext:: helpers
#   their parent tests run in a child process). All 138 fail unsigned alone
#   with CreateVm(Error(1)) and pass signed alone.
#   cpu-template-helper: 29 tests; 23 pass, 6 fail (4 no-hvf, 2 below).
#   compat-kvm-ioctls: 64 tests; 24 pass, 40 fail, all no-hvf (Error(1) at
#   hv_vm_create; counted again with the guest-debug tests, with PV time's
#   (the attribute's refusal where PV time is not offered is checked
#   without a VM: test_the_attribute_is_enxio_where_pv_time_is_not_offered,
#   which passes on the runners, macOS 26), and with the
#   vCPU thread's latency tier: test_a_wfi_ends_when_its_timer_is_due
#   fails on a runner before it makes its VM, at its own requirement of a
#   foreground process, since the runners' processes are coalesced as
#   background ones: timer-coalescing.py's output in the same job).
#   Pass (names, a name in two of a crate's binaries counted once):
#   acpi-tables 22, clippy-tracing 17, firecracker 89, rebase-snap 3,
#   snapshot-editor 6, utils 16, wick-ext 1, wick-version 2, compat-libc 30,
#   compat-memfd 3, compat-std 1, compat-userfaultfd 5, compat-vmm-sys-util 26.
#   No tests: log-instrument, log-instrument-macros, seccompiler,
#   compat-event-manager, compat-kvm-bindings, compat-micro-http, compat-os,
#   compat-vhost, compat-vm-memory.
