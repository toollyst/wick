# Upstream integration tests that pass on Linux
# (tools/macos/integration-linux-baseline.txt) and do not pass on macOS, each
# with the reason. tools/macos/compare-integration-tests.py fails on any other
# difference, and on an entry whose tests pass.
#
# Format: <mode> <kind> <pytest node id, relative to tests/; a test function
# for all its parameters>, below a comment that gives the reason.
# mode: all, user (tools/macos/integration-tests.sh without --jailer) or
# jailer. kind:
#   row-N       a Linux feature macOS does not have yet: docs/PORTING.md row N
#   root        needs the jailer as root: run with --jailer
#   arch        tests of the x86_64 host (Apple silicon is aarch64; row 11)
#   impossible  the host cannot do it; the comment says why
#   bug         a wick bug, to fix

# The test caps Firecracker's address space from outside with prlimit(2)
# (RLIMIT_AS). macOS has no prlimit: a process reads and sets only its own
# resource limits. Nor does it take an address-space limit at all (measured
# with setrlimit on the process itself: a 64 MiB RLIMIT_AS is refused, the
# limit stays unlimited, and a 1 GiB mapping succeeds). wick_macos's prlimit
# raises ENOSYS rather than pretend.
all impossible integration_tests/functional/test_api.py::test_api_machine_config

# Ctrl+Alt+Del is the x86 i8042 keyboard controller's: upstream skips the
# test off x86_64 ("not yet implemented on aarch64"), and the Linux results
# are x86_64's.
all arch integration_tests/functional/test_api.py::test_send_ctrl_alt_del

# Upstream's memory monitor (host_tools/memory.py) fails a test whose VMM
# holds more than 5 MiB resident besides guest memory (7 MiB while a
# snapshot is taken). On macOS the VMM's own memory is at that budget: the
# process's regions as wick_macos.memory_maps reads them (proc_pidinfo)
# peak at 4.7 to 4.9 MiB for a booted microVM of test_api.py and at 5.02
# to 5.19 MiB where the monitor trips: Firecracker's text 2.3 to 2.5 MiB,
# malloc 1.4 to 1.6 MiB, thread stacks 0.2 to 0.35 MiB; an idle Firecracker
# holds 3.0 MiB. Apple silicon maps 16 KiB pages, where Linux's aarch64 and
# x86_64 hosts map 4 KiB ones, so every page a thread, an allocation or a
# code path touches costs four times as much. A pmem device whose file is
# also a drive's counts the file's pages the drive read: macOS reports a
# shared file mapping's resident pages per file, not per process (14 MiB of
# pmem in test_get_full_config_after_restoring_snapshot, whose guest never
# touches the pmem device). To do: bring the VMM's own memory under the
# budget. Only a test whose every failing phase failed with this error is
# excused.
all bug failure:host_tools.memory.MemoryUsageExceededError

# The test looks in Firecracker's log for the API socket by its path in the

# Firecracker binds the socket below the jail's directory and its error
# names that path.
user root integration_tests/functional/test_api_server.py::test_api_socket_in_use

# A static executable: macOS has none. Its system calls are libSystem's

# The ELF debug file Linux's release splits off with objcopy, its sections
# read with readelf -S. A Mach-O binary has no ELF sections; macOS keeps
# DWARF in a dSYM bundle, Mach-O sections readelf does not read
# (tools/macos/integration/bin/readelf lists symbols only).
all impossible integration_tests/functional/test_binary.py::test_release_debuginfo
