# The workspace's unit tests that do not pass on Windows, each with its reason.
#
# tools/windows/check-unit-tests.py runs the packages' tests as upstream's CI
# does on Linux (host_tools/cargo_build.py cargo_test: RUST_TEST_THREADS=1,
# --no-fail-fast; tools/linux/unit-tests.sh does the same) and fails on:
#   - a failure not listed here;
#   - an entry whose test passes (without --whp; with --whp, on the WHP PC,
#     the whp-pc entries must pass);
#   - an entry naming no test the run reported.
# So nothing goes unrun silently, and the list cannot rot.
#
# Format: <kind> <package> <test path>; the comment after a group gives its reason.
#   whp-pc      makes a VM and fails on CI's windows-latest, for the reason
#               its group's comment gives (measured; some not yet root-caused);
#               must pass on the WHP PC (--whp), where a failure is a bug
#   whp-limit   needs what WHP does not do (measured); fails on every host
#   error-text  the test builds Linux's error text from a Linux errno number
#   linux-path  the test names a Linux path or builds JSON from a host path
#   bug         a wick bug or an unexplained difference, to fix (root cause
#               first)
#
# First measured on Windows Server 2022 without WHP (fc-win), the tree of
# 51be34e plus the MSR change, 4 test threads: vmm --lib 974 tests, 794 pass,
# 168 fail, 12 ignored (the ext:: child-process helpers, which their parent
# tests run). Of the 168, five passed alone and failed only beside others
# (balloon test_hinting_invalid_cmd, _misaligned_value, _no_cmd_set; block
# test_read_write; vsock muxer test_muxer_killq): they read the process-wide
# METRICS. Upstream runs its unit tests one at a time for that reason
# (RUST_TEST_THREADS=1, above), as does this checker, so they are not
# entries; their collision is not a Windows difference and is not checked
# on Linux.
#
# CI's windows-latest has WHP (run 43277608081): vmm's tests make partitions,
# map guest memory and run vCPUs there, and the 18 vmm entries and one
# cpu-template-helper entry then listed for a host without WHP passed, so
# they left the list. What still fails there is listed by its measured
# cause below.
#
# Run 43277608081 also failed every guest-memory map of vmm's process after
# builder's test_attach_balloon_device, and of cpu-template-helper's after
# template::dump's test_dump, with ERROR_INVALID_PARAMETER (87): about 100
# entries, then listed whp-pc. The cause was kvm-ioctls' irqfd watcher,
# which held its VM by a strong reference until the VM was dropped, so a VM
# that registered an irqfd was never dropped. Those two are the first tests
# of their processes, in name order, to make a microVM, whose devices
# register irqfds (device_manager/legacy.rs:68), and both pass; WHP maps
# guest memory for one partition of a process at a time, and the kept VM's
# memory refused every later map. 28e7fb8 holds the VM weakly, and in run
# 43292883636 (same runner image, 20261103.298.1) the about 100 pass;
# kvm-ioctls' test_a_vm_with_an_irqfd_is_dropped_with_its_last_reference
# passes in its WHP step, and MAPTEST there shows a refused map leaves no
# state behind and a kept VM refuses every later map. The whp-pc entries
# that still failed there were each given their measured cause below; none
# is whp-pc now.
#
# The checker reports every disagreement of a run (it does not stop at the
# first), so one run is enough to bring the list in step.
